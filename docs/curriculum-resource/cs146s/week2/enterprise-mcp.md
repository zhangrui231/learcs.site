## 中文翻译

### 企业级 MCP

Model Context Protocol（MCP）正在改变 AI Agent 与外部工具和数据源交互的方式。但在企业环境中部署 MCP 服务器带来了一系列新的挑战：安全、可扩展性、可观测性和治理。

#### MCP 在企业中的价值

在企业环境中，MCP 的价值主张特别强：

- **统一工具接口**：不同团队、不同服务都可以通过统一的 MCP 协议暴露工具，Agent 不需要为每个 API 学习特定的调用方式。
- **权限与治理**：企业可以在 MCP 服务器层面实施统一的访问控制，而不是在每个 Agent 客户端分别实现。
- **可观测性**：所有工具调用都经过 MCP 服务器，可以集中记录、审计和监控。

#### 关键设计考量

**1. 远程 vs 本地传输**

MCP 支持两种传输模式：stdio（本地）和 HTTP+SSE（远程）。企业部署通常需要远程模式，因为：

- Agent 客户端可能运行在云端，而不是本地机器上
- 需要集中管理 MCP 服务器，而不是在每个客户端部署
- 远程模式支持多客户端共享同一个服务器实例

**2. 认证与授权**

企业 MCP 服务器需要完整的认证链：

- **客户端认证**：Agent 客户端需要向 MCP 服务器证明自己的身份
- **用户授权**：MCP 服务器需要知道当前用户是谁，以便实施最小权限原则
- **工具级权限**：不同用户/角色对同一个工具可能有不同的权限级别

OAuth 2.0 是目前推荐的企业级 MCP 认证方案。

**3. 安全边界**

MCP 服务器是企业安全边界的一部分：

- 所有工具调用应该经过输入验证和输出过滤
- 敏感操作应该需要额外的确认步骤
- 工具描述本身可能泄露内部架构信息，需要做信息脱敏

**4. 可扩展性**

企业级 MCP 部署需要支持：

- **多租户**：不同团队或项目共享同一个 MCP 服务器，但工具集和权限不同
- **负载均衡**：高并发下，多个 MCP 服务器实例需要做负载均衡
- **工具发现**：当工具数量很多时，支持动态工具发现而不是一次性加载所有工具

#### Cloudflare 的实践

Cloudflare 在自己的基础设施上部署 MCP 服务器，利用了其全球边缘网络：

- MCP 服务器运行在 Cloudflare Workers 上，靠近用户
- 利用 Cloudflare 的 Access 做认证
- 使用 Durable Objects 管理有状态的会话
- 通过 Cloudflare 的可观测性栈监控所有工具调用

#### 对 Agent 设计的影响

企业级 MCP 带来的最重要变化是：Agent 不再是孤立的工具调用者，而是一个受治理的系统的一部分。这意味着：

- Agent 的工具调用会被审计
- 工具的可用性和行为可能在运行时变化（管理员调整权限、下线工具等）
- Agent 需要优雅地处理工具不可用的情况
- 错误处理变得更重要——企业环境中的工具失败不应该导致 Agent 停止工作

#### 结论

MCP 在企业环境中不仅仅是"让 Agent 调用 API"——它是企业 AI 治理架构的核心组件。一个好的企业 MCP 部署应该让 Agent 更强大，同时让企业保持对工具访问的完全控制。
