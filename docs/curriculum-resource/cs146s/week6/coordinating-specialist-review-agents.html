Coordinating Specialist Review Agents at Scale —— 大规模协调专业审查 Agent

原文链接：https://blog.cloudflare.com/ai-code-review

来源：Cloudflare Blog

来源：CS146S Week 6 Reading

请通过上方原文链接阅读完整英文原文。

中文翻译​

大规模协调专业审查 Agent​

在 Cloudflare 这样的规模下，每天都有数千个 PR 被创建。传统的人类代码审查已经成为瓶颈。我们的解决方案是部署多个专门的 AI 审查 Agent，每个负责一个领域，然后在 PR 级别协调它们的输出。

架构概览​

我们的 AI 代码审查系统由以下组件组成：

1. PR 事件触发器

当 PR 被创建或更新时，GitHub webhook 触发审查流水线。流水线评估 PR 的元数据（影响的文件、变更类型、作者），决定启动哪些审查 Agent。

2. 专业审查 Agent

每个 Agent 专注于一个维度：

Agent关注点触发条件
安全审查输入验证、注入、认证绕过任何涉及认证、数据库、用户输入的变更
性能审查N+1 查询、不必要的循环、内存泄漏任何涉及数据库、缓存、批处理的变更
正确性审查边界条件、空值处理、并发问题任何涉及核心业务逻辑的变更
风格审查命名、结构、约定遵循所有 PR
文档审查是否更新了相关文档任何 API 变更

3. 协调层

协调层负责：

  • 决定启动哪些 Agent（不是每个 PR 都需要所有 Agent）
  • 收集各 Agent 的输出
  • 去重和合并重叠的发现
  • 按严重程度排序
  • 生成统一的审查评论

4. 反馈回路

每个 Agent 的输出都会被跟踪：

  • 开发者是否采纳了建议
  • 建议是否是 false positive
  • 是否有 Agent 漏掉了重要问题

这些数据用于持续改进 Agent 的提示词和规则。

关键设计决策​

并行 vs 串行执行

我们选择并行执行所有相关 Agent，然后在协调层合并结果。串行执行会让审查时间过长——在高 PR 量的环境中，速度很重要。

评论策略

AI 审查评论需要在不骚扰开发者的前提下提供价值：

  • 每个 PR 最多 5 条 AI 评论（避免信息过载）
  • 按严重程度排序（阻止合并 > 建议修改 > 信息性）
  • 对每条评论说明"为什么"和"怎么修"
  • 如果 Agent 不确定，明确标注"可能的问题"

与人类审查的关系

AI 审查不是替代人类审查——而是在人类审查之前过滤掉可自动检测的问题。人类审查者看到的是已经经过 AI 预筛的 PR，可以专注于更高层次的设计和逻辑问题。

规模化挑战​

在 Cloudflare 的规模下，我们遇到了几个非显然的问题：

1. Agent 之间的矛盾

不同的 Agent 有时会给出矛盾的建议（如安全 Agent 说"加更多验证"，性能 Agent 说"减少不必要的检查"）。协调层需要识别这种矛盾并做仲裁。

2. 上下文窗口限制

大型 PR 可能包含数千行变更。单个 Agent 无法在一次调用中处理整个 PR。我们的解决方案是按文件分组，让每个 Agent 只看相关的文件，然后在协调层合并。

3. 延迟管理

开发者期望 PR 审查在几分钟内完成。我们通过并行执行和优先级队列来管理延迟——安全和正确性审查优先于风格和文档审查。

结论​

大规模 AI 代码审查的关键不是"一个强大的 Agent"——而是"多个专门 Agent 的协调系统"。每个 Agent 做好一件事，协调层将它们组合成统一的审查体验。这种架构既灵活（可以独立添加和改进 Agent）又可扩展（并行处理满足高吞吐需求）。
